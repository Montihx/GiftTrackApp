# Дополнения к ТЗ «Gift Track + Flip» (решения по замечаниям)

Замечания к ТЗ рассмотрены; ниже — что принято, в какой этап и что отложено. Источник правды по основным требованиям остаётся ТЗ.

## Принято в Track (до релиза v1.0) — порядок работ
1. **Админка (команды бота, `bot/admin.py`)**: выдача и отзыв подписки, бан/разбан, статистика (пользователи, подписки, фильтры, события и алерты за сутки), просмотр `nft_dlq` (последние N и повторная обработка), рассылка пользователям. Доступ — только `ADMIN_IDS`.
2. **Алерты администратору**: сообщение в Telegram, если упал сервис (resolver, listener-market, бот), источник на паузе дольше N минут, растёт `lag` группы `g:dispatcher` или длина `nft_dlq`, не авторизована сессия Telethon.
3. **Данные и бэкапы**: Redis с AOF (`--appendonly yes` — уже в compose); бэкап PostgreSQL по расписанию (`scripts/backup.sh`, хранение N копий; `scripts/update_server.sh` уже делает дамп перед обновлением); очистка старых данных (снимки флоров, кэши, потоки с `MAXLEN`).
4. **Приватность**: команда `/delete_me` (удаляет пользователя, фильтры, избранное, подписки), текст политики конфиденциальности в `/help`; в Telethon-аккаунте только чтение, лимиты запросов.
5. **Фильтры**: тихие часы и кнопка «Тестовое уведомление» (Track).
6. **Деплой**: HTTPS и firewall — инструкция в README (сервер вне репозитория), тестовый бот через отдельный `BOT_TOKEN` в `.env`, откат — восстановление дампа и `git checkout` предыдущего коммита (скрипт обновления это печатает).

## Принято во Flip (этапы 10–13)
- **Журнал исходов сигналов** (выкуплен/продан/цена изменилась через N минут) и кнопка «сигнал полезен / нет» — для калибровки порогов спреда и ликвидности.
- **Холодный старт**: пока нет `sales_history` и медиан, Flip-сигналы идут только с базисом `model_floor`/`gift_floor` и пометкой `low_confidence`; backfill с лимитом запросов и паузами.
- **Бэктест фильтра** («сколько сигналов дал бы за 7 дней»), готовые пресеты.
- **Данные**: защита от манипуляций ценами между своими адресами (исключать продажи между связанными адресами), переименование коллекций (таблица алиасов).
- **Деградация источников**: circuit breaker по маркету (уже есть пауза при отказе) и понятный статус пользователю в приложении.

## Отложено / не делаем сейчас
- Dev/staging/prod окружения и полноценный CI/CD: хватает одного сервера и тестового бота.
- Монетизация (пробный период, промокоды, рефералы, смена тарифа, возвраты) — после согласования тарифов с заказчиком.
- Режим replay для демо — после релиза v1.0.
- Юридическое (правила использования API маркетов): неофициальные API используются без обхода защиты; при отказе источник отключается.

## Не нужно
- `AGENTS.md`: роль выполняет `CLAUDE.md` (правила, соглашения, как работать).

## Уточнения по оформлению (от заказчика)
- Все ссылки в алертах — только на Telegram (`t.me/nft/…`, `t.me/<username>`, `tg://user?id=`): никаких GetGems, Tonviewer и других сторонних сайтов.
- Кнопка «Написать владельцу» — в клавиатуре алерта, как в референсном боте (скриншоты заказчика).
- После работ по ТЗ — очистка: удалить лишние функции, мёртвый код и неиспользуемые файлы (скан TonAPI для листингов/апгрейдов, старый GraphQL-листенер GetGems, Tonviewer-шаги резолвера, неиспользуемые настройки).
