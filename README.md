# Gift Track Bot — клон @GiftTrackBot

Бот мониторит **апгрейды (mint)**, **листинги** и **продажи** Telegram-подарков (NFT на TON)
и шлёт уведомления («ЛИСТИНГ», «GIFT SOLD!») с резолвингом владельца в Telegram-аккаунт.
Фильтры настраиваются в Telegram Web App (TWA).

## Стек

Python 3.11 · FastAPI · Aiogram 3 · Pytoniq · Telethon · PostgreSQL 16 ·
Redis 7 · React 18 + Vite (TWA) · Docker Compose · Nginx · CryptoBot API

## Сервисы (docker-compose)

| Сервис | Команда | Назначение |
|---|---|---|
| `postgres`, `redis` | — | хранилище и очереди |
| `migrate` | `alembic upgrade head` | миграции БД (одноразово перед стартом) |
| `bot` | `python -m bot.bot_main` | Aiogram (polling) + рассылка уведомлений |
| `listener-market` | `python -m bot.market_main` | скан TonAPI (флоры, количество, атрибуты; продажи) — нужен `TONAPI_KEY` |
| `resolver` | `python -m bot.resolver_main` | фоновый Telethon-воркер (опционально) |
| `updater` | `python -m services.updater` | seed-каталог и метаданные коллекций |
| `twa-api` | `uvicorn api.main:app` | REST + SSE для TWA, вебхук оплаты |
| `twa-frontend` | nginx со статикой Vite | интерфейс TWA |
| `nginx` | — | reverse proxy на портах 80/443 |

```

```

## Быстрый старт

```bash
git clone https://github.com/Montihx/GiftTrackApp.git && cd GiftTrackApp
cp .env.example .env
nano .env                       # BOT_TOKEN, CRYPTOBOT_TOKEN, ADMIN_TG_IDS, DB_PASS, TWA_URL, TONAPI_KEY
# на слабом сервере (< 2 ГБ RAM) собирайте по одному, иначе сборка может повесить машину:
COMPOSE_PARALLEL_LIMIT=1 docker compose build
docker compose up -d
docker compose ps
docker compose logs -f bot
```

**Обновление уже работающего сервера** (подходит и для очень старой версии; данные в docker-томах
сохраняются) — одной командой (бэкап `.env` и базы, проверка локальных правок, `git pull`, новые настройки в
`.env` без изменения старых, запрос недостающих ключей со скрытым вводом, сборка, запуск, вход Telegram
по QR, проверка логов):

```bash
cd ~/gifts/GiftTrackApp
git fetch origin main && git show origin/main:scripts/update_server.sh > /tmp/gt_update.sh && bash /tmp/gt_update.sh
```

`migrate` отрабатывает автоматически, остальные сервисы ждут его завершения.
Порты postgres/redis/api/frontend привязаны к `127.0.0.1`, наружу открыты
только 80/443 через nginx.

Все python-сервисы используют один образ `gifttrack-app` (общий кэш слоёв), фронтенд
собирается отдельно. Если сервер падает при сборке — добавьте swap:
`sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile`.

### Важно про `.env`

- `DB_PASS` в `.env` должен совпадать с паролем в `DB_URL`
  (`postgresql+asyncpg://gt:<DB_PASS>@postgres/gifttrack`).
- **Никогда не публикуйте токены** (скриншоты, чаты, коммиты). Если токен утёк,
  перевыпустите его: `/revoke` в @BotFather, ключ в настройках CryptoBot.
  `.env` добавлен в `.gitignore`.

### HTTPS и автопродление сертификата

Боевой хост: `gifttrack.155.248.234.68.sslip.io`. Сертификат Let's Encrypt лежит
в `/etc/letsencrypt/live/gifttrack.155.248.234.68.sslip.io/` и монтируется в nginx
только на чтение; `nginx.conf` уже содержит редирект 80 → 443 и TLS-блок. Порт 3000
хоста не используется (фронтенд слушает `127.0.0.1:3001`). Для другого домена
замените имя в `nginx.conf` и выпустите сертификат через certbot.

Автопродление (certbot на хосте, standalone: на время продления nginx останавливается).
Разрешите `ubuntu` запускать certbot без пароля: `sudo visudo -f /etc/sudoers.d/certbot`,
строка `ubuntu ALL=(root) NOPASSWD: /usr/bin/certbot`. Затем `crontab -e`:

```cron
0 4 * * * cd ~/gifts/GiftTrackApp && docker compose stop nginx && sudo -n certbot renew --quiet; docker compose start nginx
```

`start` стоит после `;`, чтобы nginx поднялся, даже если продление не удалось.
Telegram открывает TWA только по HTTPS; адрес задаётся в `TWA_URL` и в Menu Button у @BotFather.

### Telethon: cold path резолвера (необязательно)

Воркер `resolver` сканирует bio известных пользователей (username из `users`,
истории владельцев и `wallet_tg_map`) на TON-адреса (`EQ…`/`UQ…`/raw/`ton://`),
строит индекс «адрес → пользователь» в Redis и разбирает очередь
`telethon_resolve_queue`: найденные владельцы пишутся в `wallet_tg_map`
(`source=telethon`) и кэш. Telegram не умеет искать по тексту bio, поэтому
охватываются только известные боту пользователи.

Настройка: заполните `API_ID`, `API_HASH`, `PHONE` в `.env` (лучше отдельный
аккаунт, не основной), затем один раз войдите (код из Telegram):

```bash
# вход по QR (код вводить не нужно): Telegram → Настройки → Устройства → Подключить устройство
docker compose run --rm -it resolver python -m bot.resolver_main --login-qr
# или по коду из Telegram:
docker compose run --rm -it resolver python -m bot.resolver_main --login
docker compose restart resolver
```

Сессия хранится в томе `tgsessions`. Без авторизации воркер просто простаивает
и пишет подсказку в лог. Пауза между запросами, размер пачки и период повторного
скана настраиваются: `BIO_SCAN_DELAY` (2 с), `BIO_SCAN_BATCH` (100),
`BIO_RESCAN_DAYS` (7), `BIO_CYCLE_SECONDS` (600). `FloodWait` соблюдается автоматически.

## Источники данных

**Каталог коллекций** — `db/seed/gift_collections.json`: 21 коллекция Telegram Gifts с адресами
контрактов и иконками (`nft.fragment.com/collection/<slug>.webp`). Каждый адрес проверен on-chain
через TonAPI: коллекция в whitelist TonAPI, `approved_by: getgems`, метаданные отдаются с
`nft.fragment.com/collection/<slug>.json`. В TonAPI много поддельных коллекций с тем же именем и
описанием — по имени адрес не выбирать. Seed применяется при старте `updater` (идемпотентно;
плейсхолдер `tg_gift:<slug>` заменяется адресом, пустая иконка дозаполняется).

**Новые коллекции — автоматически (нужен `TONAPI_KEY`).** `services/gift_discovery.py` в
`listener-market` раз в `TONAPI_DISCOVERY_INTERVAL` (1 ч) читает `TONAPI_DISCOVERY_PAGES` (5) страниц
NFT кошелька «Fragment Gift Minter» (`0:158136…6c07`): улучшенные, но не выведенные подарки лежат
у него, поэтому там видны почти все коллекции, включая только что вышедшие (на странице из 1000
NFT — 100+ коллекций). Новая коллекция добавляется в БД (`source='tonapi'`, имя в единственном
числе, иконка с fragment), только если её контракт развёрнут этим кошельком и метаданные отдаются
с `nft.fragment.com/collection/<slug>.json` — подделки (их в TonAPI десятки на каждую коллекцию)
так не проходят. Отклонённые адреса запоминаются в Redis. Добавленную коллекцию TonAPI-sync
начинает сканировать в том же цикле, она сразу появляется на витрине и в форме фильтров.
Выключить: `TONAPI_DISCOVERY_ENABLED=false` (останется seed-каталог).

**Реальное время — поток переводов NFT (нужен `TONAPI_KEY`, хватает free-тарифа).**
`services/tonapi_stream.py` держит SSE-соединение `GET /v2/sse/accounts/transactions?accounts=ALL&operations=0x5fcc3d14`
— каждую финализированную транзакцию «перевод NFT» по всей сети TON. Листинг, продажа, снятие с продажи и
перевод — это всё переводы NFT. Адрес проверяется по `processed_nfts` локально (чужие NFT отбрасываются без
запросов к API); для наших подарков через `TONAPI_STREAM_DELAY` (2 с) делается один `GET /v2/nfts/{addr}` →
«ЛИСТИНГ» / «GIFT SOLD!» за секунды, флор коллекции и модели снижается сразу. Квоту почти не тратит: запрос —
только на перевод нашего подарка. Запросы потока идут вне очереди: пока такой запрос ждёт, полный скан
слот лимита не получает (`RateLimiter(high=True)`). Если индексатор TonAPI ещё не обновил подарок, он
перепроверяется через `TONAPI_STREAM_RECHECK` (8 с). Штатные обрывы соединения сервером — переподключение
сразу, с `Last-Event-ID`. При обрыве — переподключение с backoff; пропущенное догонит полный скан.
Поток работает для коллекций, у которых завершён первый проход скана.

**TonAPI (основной источник, нужен `TONAPI_KEY`)** — `services/tonapi_sync.py` в `listener-market`:
постранично читает `GET /v2/nfts/collections/{addr}/items` и сравнивает с прошлым состоянием
предмета (Redis-хэш на коллекцию):

- новый листинг или смена цены → `nft_listings` → уведомление «ЛИСТИНГ»;
- выставленный предмет сменил владельца → строка в `sales` + `nft_sales` → «GIFT SOLD!»
  (цена в TON и ≈USD по курсу `GET /v2/rates`);
- по завершении прохода — floor коллекции (+снапшот для графика и 24h change), floor и количество
  по моделям/фонам/символам, `items_count`.

Особенности живого API (проверено в 2026-11): цена листинга приходит как
`{"currency_type": "native", "token_name": "Gram", ...}`; поле `index` у подарков — хэш, номер
берётся из `metadata.name` («Plush Pepe #2675»); ещё не выведенные в блокчейн подарки принадлежат
«Fragment Gift Minter» (владелец неизвестен); маркет — `sale.market.name` («Getgems Sales»,
«Marketapp Marketplace»). Первый проход каждой коллекции — без уведомлений.

**Лимиты.** Free-тариф tonconsole — 1 RPS (проверено: ~3–10% запросов получают 429 и проходят
с ретраем); все запросы процесса идут через общий limiter (`TONAPI_RPS`). За цикл на коллекцию
читается до `TONAPI_PAGES_PER_CYCLE` страниц по 1000 items; крупные коллекции проходятся за
несколько циклов, и их floor обновляется раз в проход. Замеры (2026-11):

| Каталог | Items | Запросов за цикл | Цикл на 1 RPS | Полный проход самой крупной |
|---|---|---|---|---|
| seed, 21 коллекция | ~217 тыс. | ~65 | ~1 мин | ~12 мин (Homemade Cake, 34k) |
| с автообнаружением, ~122 коллекции | ~1,5 млн | ~330 | ~5–6 мин | ~2 ч (Lol Pop, 70k) |

Листинги и продажи приходят из потока за секунды на любом тарифе — скан нужен для floors, атрибутов
и как страховка. Чтобы скан успевал на free-тарифе, «горячие» коллекции (на которые у пользователей есть
фильтры или избранное) сканируются каждый цикл и первыми, остальные — раз в `TONAPI_COLD_EVERY` (3) цикла.
Рост floor крупной коллекции (продан самый дешёвый лот) виден после её прохода: на free-тарифе — до ~2 ч,
на Lite ($9.9, 10 RPS) — ~15 мин; снижение floor — сразу из потока. Тарифы: tonapi.io → Pricing.
Ключ общий для `listener-market` и `twa-api` (цена предмета на витрине) — учитывайте это в `TONAPI_RPS`.

**Без ключа** витрина показывает seed-каталог, floor «—», график — empty-state; `listener-market`
работает через GetGems GraphQL, `updater` считает floors через GetGems.

**Маркет подарков Telegram (официальный API, бесплатно; нужен Telethon-аккаунт резолвера).**
`services/telegram_market.py` в сервисе `resolver`: раз в `TG_MARKET_CATALOG_INTERVAL` (5 мин)
`payments.getStarGifts` — соответствие подарков Telegram нашим коллекциям и флор маркета в Stars с числом
листингов (Redis `tg_market:floor:{cid}`) по всем коллекциям одним запросом; каждые `TG_MARKET_INTERVAL`
(2 с) — `payments.getResaleStarGifts` по одной коллекции (новые сверху; сначала коллекции с фильтрами/
избранным). Новый листинг или смена цены → «ЛИСТИНГ» с маркетом «Telegram Market», ценой в TON и/или ⭐ и
ссылкой `t.me/nft/<slug>`; владелец берётся из Telegram — «Написать владельцу» работает без резолвера.
Первый опрос коллекции — без уведомлений. FloodWait соблюдается. Дедупликация идёт по базовой цене (⭐; для листингов за TON — TON), потому что цена в TON у
листинга за Stars — пересчёт по курсу и «плавает». Предохранитель `TG_MARKET_MAX_NEW` (10): если за один
опрос «новыми» оказалось больше — рассылка пропускается (сбой дедупликации не превращается в спам). Вход аккаунта — см. «Telethon» выше;
лучше отдельный аккаунт.

**Владелец и уведомления «АПГРЕЙД».** Адрес кошелька почти никогда не приводит к Telegram-аккаунту, поэтому
контакт ищется по slug подарка (`t.me/nft/PlushPepe-727`): `services/owner_lookup.py` — dispatcher кладёт slug
в Redis-очередь, воркер сервиса `resolver` (тот же Telethon-аккаунт) вызывает `payments.getUniqueStarGift` и
возвращает владельца, если он не скрыл его в Telegram. Ответ кэшируется (1 ч; «скрыт» — 5 мин); если воркер не
запущен (нет входа Telethon), уведомление не ждёт. В фильтре есть галочка «Только если можно написать владельцу»
(включена по умолчанию): без контакта такой фильтр листинги и апгрейды не получает; «GIFT SOLD!» не зависит от неё.
«АПГРЕЙД» отправляется, когда в коллекции после первого прохода скана появился новый предмет: для коллекций с
фильтрами скан идёт каждый цикл, поэтому задержка — секунды-минуты (большие коллекции — дольше). Пачка новых
предметов больше `UPGRADE_BURST_MAX` (20) за раз не рассылается (это сбой состояния, а не апгрейды).
Сервис `listener-ton` (Tonviewer) удалён: его API недоступен.

**Другие маркетплейсы.** Листинги on-chain маркетов (GetGems, Marketapp и др.) TonAPI отдаёт сам,
имя маркета берётся из `sale.market.name`. Portals, Tonnel и MRKT публичного API не имеют: их
внутренние API закрыты защитой от ботов (Tonnel — Cloudflare, MRKT — лимит «contact the support») и
требуют входа аккаунтом в их мини-приложения. Обходить защиту чужих сервисов мы не будем, поэтому они не
подключены; офчейн-рынок покрывает официальный маркет Telegram.

## Переменные окружения (дополнительно к `.env.example`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `TONAPI_KEY` | пусто | ключ tonconsole.com; пусто → только seed-каталог (скан блокчейна выключен) |
| `TONAPI_POLL_INTERVAL` | 15 | пауза между циклами TonAPI-синхронизации, с |
| `TONAPI_RPS` | 0.8 | лимит запросов к TonAPI на процесс (free-тариф — 1 RPS; ровно 1.0 даёт частые 429) |
| `TONAPI_PAGES_PER_CYCLE` | 3 | страниц по 1000 items на коллекцию за цикл |
| `TONAPI_STREAM_ENABLED` | true | события в реальном времени из SSE-потока переводов NFT |
| `TONAPI_STREAM_DELAY` | 2 | пауза перед запросом NFT после события (индексатор TonAPI), с |
| `TONAPI_STREAM_RECHECK` | 8 | повторная проверка подарка, если индексатор TonAPI не успел, с (0 — выкл) |
| `TONAPI_COLD_EVERY` | 3 | коллекции без фильтров/избранного сканируются раз в N циклов |
| `TONAPI_DISCOVERY_ENABLED` | true | автодобавление новых коллекций Telegram Gifts |
| `TONAPI_DISCOVERY_INTERVAL` | 3600 | период автообнаружения, с |
| `TONAPI_DISCOVERY_PAGES` | 5 | страниц NFT минтера за один запуск автообнаружения |
| `OWNER_LOOKUP_ENABLED` | true | поиск владельца подарка по slug через Telegram (нужен вход Telethon) |
| `OWNER_LOOKUP_TIMEOUT` | 4 | сколько уведомление ждёт владельца, с |
| `UPGRADE_BURST_MAX` | 20 | больше новых предметов за раз — апгрейды не рассылаются |
| `SHOWCASE_CACHE_TTL` | 10 | кэш лёгкого списка коллекций в API, с (0 — выкл) |
| `TG_MARKET_ENABLED` | true | листинги маркета подарков Telegram (сервис `resolver`, нужен вход Telethon) |
| `TG_MARKET_INTERVAL` | 2 | пауза между запросами листингов к Telegram, с |
| `TG_MARKET_CATALOG_INTERVAL` | 300 | обновление каталога и флоров маркета Telegram, с |
| `CRYPTOBOT_API_URL` | `https://pay.crypt.bot/api` | для тестов — `https://testnet-pay.crypt.bot/api` (токен из @CryptoTestnetBot) |
| `SUB_PRICE_USD_30/60/90` | 49 / 89 / 119 | цены тарифов, $ (инвойс CryptoBot в USD, оплата TON/USDT) |
| `VITE_OWNER_USERNAME` | пусто | username владельца для «Не получается оплатить? → Написать владельцу» (build-arg фронтенда) |

**Оплата.** Вебхук CryptoBot: `/api/payments/webhook/<CRYPTOBOT_WEBHOOK_SECRET>`. Если задан
`CRYPTOBOT_TOKEN`, проверяется подпись `Crypto-Pay-Api-Signature`; повторная доставка одного
инвойса не продлевает подписку дважды (таблица `payment_invoices`). Продление активной подписки
добавляет дни к текущему сроку, истёкшей — отсчитывает от момента оплаты.

## Диагностика

| Симптом | Причина / решение |
|---|---|
| `failed to read dockerfile` для `twa-frontend` | нет `frontend/Dockerfile`, выполните `git pull` |
| `No module named bot.main` | устаревший `docker-compose.yml`, `git pull` |
| `docker compose ps` пуст | сборка упала, смотрите `docker compose up -d --build` до первой ошибки |
| SSE-поток флор-цены обрывается | в nginx должен быть блок `location ~ ^/api/collections/[^/]+/stream$` с `proxy_buffering off` |
| бот не отвечает | `docker compose logs --tail=50 bot`, проверьте `BOT_TOKEN` |
| floors «—» при заданном ключе | первый проход ещё идёт (крупные коллекции — до ~12 мин на 1 RPS); `docker compose logs listener-market` |
| `HTTP 429` от TonAPI в логах | `TONAPI_RPS` выше лимита тарифа (учтите, что ключ делят `listener-market` и `twa-api`) |
| `HTTP 401` от TonAPI | неверный `TONAPI_KEY` |
| вебхук оплаты отвечает 401 | `CRYPTOBOT_TOKEN` в `.env` не совпадает с токеном приложения, на которое настроен вебхук |

## Ограничения

- Время листинга/продажи — момент обнаружения: из потока — секунды, если событие пропущено (обрыв потока) — до прохода коллекции.
- Офчейн-листинги (подарок выставлен, но не выведен в блокчейн) поток не видит.
- Новые контракты продажи Marketapp TonAPI пока не распознаёт (нет `sale`, владелец — контракт): такие
  листинги без цены не объявляются, а их продажи видны как переводы. Getgems и старые контракты Marketapp
  распознаются полностью. Снимок «нет листинга, владелец — контракт» не порождает событий (защита от
  ложных «GIFT SOLD!»).
- Portals, Tonnel, MRKT не подключены (нет публичного API, см. «Источники данных»).
- Продажи на маркете Telegram не отслеживаются (листинг исчезает и при продаже, и при снятии — различить нельзя).
- Отличия от ТЗ: фронтенд на JavaScript (JSX), а не TypeScript.

## Данные маркета Telegram

Кроме ончейн-данных (TonAPI) показываются данные официального маркета подарков Telegram (через Telethon, резолвер):
«Выпущено» (общее число улучшенных подарков по Telegram), флор маркета Telegram рядом с ончейн-флором
(на карточке — меньший, с пометкой TG), в алертах — «Оценка» Telegram, кликабельный кошелёк продавца и
превью подарка (`t.me/nft/<slug>`) вместо баннера GetGems. Название монеты — `COIN_LABEL` (по умолчанию GRAM),
в мини-приложении — `VITE_COIN` при сборке.

## Флоры MRKT и Portals

`MARKET_FLOORS_ENABLED=true` — сервис resolver раз в круг спрашивает минимальную цену коллекции на MRKT и Portals
(`services/market_floors.py`). Вход — через мини-приложение маркета вашим Telegram-аккаунтом (`requestAppWebView`),
дальше обычные HTTPS-запросы. Маскировки под браузер нет: если маркет отвечает отказом или проверкой
(403/429/503, не-JSON), источник уходит в паузу и пишет это в лог. Tonnel не подключён: его документация требует имитации браузера.
На карточке показывается самый низкий флор среди ончейна и этих маркетов (с пометкой источника), на странице коллекции — каждый отдельно.
Поля ответов неофициальные; первый ответ каждого маркета пишется в лог (`[market_floors] … поля листинга`) — по нему видно, верно ли разобрана цена.

## Фильтры: две галочки, номер и цена

В форме фильтра «Только если можно написать владельцу» разделено на две галочки: для листингов (`require_owner`) и для апгрейдов
(`require_owner_upgrade`). Добавлены диапазоны «Номер подарка» (из `#727` / slug `PlushPepe-727`) и «Цена листинга» (в монете).
Если диапазон задан, а номер или цена события неизвестны — уведомление не отправляется. Миграция `0006` переносит прежнюю галочку в оба флага.

## Новые коллекции без данных

Пока ончейн-скан не дошёл до новой коллекции, её модели, фоны и символы берутся у Telegram
(`payments.getStarGiftUpgradeAttributes`, резолвер, не больше 3 коллекций за обновление каталога).
Заполняются только коллекции без атрибутов; Telegram-«pattern» хранится как «Символ». Ончейн-синхронизация позже дополняет те же строки.

## Допущения и расхождения с ТЗ «Gift Track + Flip»

Работа ведётся по ТЗ; готовый код не переписывается (раздел «Приоритет» ТЗ), расхождения закрываются поэтапно. Flip (этапы 10–13) не начат — ждёт команды «Flip».

Принятые решения:
- **Фронтенд остаётся на JSX** (правило проекта), токены и анимации из раздела 19 берутся без TypeScript и без `lucide-react` (иконки — inline SVG). Переход на TypeScript — отдельный этап после релиза Track.
- **Имена потоков Redis сохранены** (`nft_upgrades`, `nft_listings`, `nft_sales`), а не `ev:*` из ТЗ: переименование ничего не даёт, а готовые сервисы публикуют в эти ключи. DLQ: `nft_dlq`.
- **GRAM** — нативная монета сети (раньше TON), курс к TON 1:1 (подтвердить у заказчика). Название задаёт `COIN_LABEL`.
- **Маркеты:** официальный API GetGems платный (не используется); MRKT и Portals подключены через неофициальные API без обхода защиты (источник уходит в паузу при отказе); Tonnel не подключается — его API требует имитации браузера.

Закрыто по ТЗ (раздел 5.2 и 5.4): диспетчер читает потоки через consumer group `g:dispatcher` (`XREADGROUP` + `XACK`), до `DISPATCH_MAX_ATTEMPTS` попыток с экспоненциальной паузой, затем событие уходит в `nft_dlq`; зависшие сообщения (pending дольше `DISPATCH_CLAIM_IDLE_MS`) забираются `XAUTOCLAIM`; дедупликация событий `dedup:ev:*` (TTL `DISPATCH_DEDUP_TTL`).

Расхождения, ещё не закрытые: EN/RU-локализация и дисклеймер, `mypy`, таблицы `gifts`/`listings`/`offers`/`sales_history`/`notifications`/`fx_rates` (нужны в основном для Flip), 5 вкладок TWA по разделу 19.

### Лимиты отправки, подписка, тарифы (ТЗ 8.7, 13)

- **Лимиты** (`services/rate_limit.py`): глобально `SEND_RATE_GLOBAL`=25 сообщений/с, на пользователя `SEND_RATE_USER_SEC`=1/с и `SEND_RATE_USER_MIN`=20/мин. Секундные лимиты ждут слот, минутный отбрасывает сигнал и копит счётчик: перед следующим сообщением пользователю уходит одна сводка «Ещё N сигналов не показано». `429` — ждём `retry_after` и повторяем один раз, `403` (бот заблокирован) — пользователю не пишем сутки. Ошибка Redis лимитера — fail-open (алерт не теряется).
- **Доступ по подписке:** `SUBSCRIPTION_REQUIRED=true` — алерты получают только пользователи с активной платной подпиской (`sub_plan != free` и `sub_expires_at` в будущем). По умолчанию выключено (`false`), чтобы не отрезать владельца: сначала выдайте себе подписку (команда админа в боте), потом включайте.
- **Тарифы Track** (подтверждены референсом): 1 месяц — 49 $ / 30 дней, 2 месяца — 89 $ / 60 дней, 3 месяца — 119 $ / 90 дней (`SUB_PRICE_USD_30/60/90`). Оплата CryptoBot в USD.
- **Подписка одна на оба режима** (решение заказчика): Track и Flip открываются одной и той же подпиской 49 / 89 / 119 $; отдельных планов `track`/`flip`/`bundle` и разового «вечного доступа» не будет. Во Flip-вкладках без подписки показывается тот же экран оформления.

### Апгрейды из Telegram (контакт владельца)

Ончейн-апгрейды приходят, только когда подарок выведен в TON, а владелец там — кошелёк без Telegram-аккаунта. Поэтому
`services/telegram_upgrades.py` (сервис resolver, `TG_UPGRADES_ENABLED`) смотрит апгрейды со стороны Telegram: номера подарков идут
подряд (`PlushPepe-N`), новый апгрейд — подарок со следующим номером; `payments.getUniqueStarGift` отдаёт владельца
(`owner_id` / `owner_name`), и событие в `nft_upgrades` приходит сразу с контактом (кнопка «Написать владельцу»).
Горячие коллекции (фильтры/избранное) опрашиваются каждый круг, холодные — по несколько за круг; долгий простой не вызывает
рассылки старых апгрейдов (`TG_UPGRADES_SKIP_GAP`). Дубль того же улучшения из блокчейна гасится дедупликацией по (коллекция, номер).
Если владелец скрыл подарок, контакта нет, и алерт зависит от галочки «Апгрейды: только если можно написать владельцу».

### Источники событий и их приоритет

- **Листинги:** MRKT и Portals (`services/market_listings.py`, `MARKET_LISTINGS_ENABLED`) — приоритетные источники; затем маркет Telegram (`TG_MARKET_ENABLED`), единственный с контактом продавца.
- **Апгрейды:** со стороны Telegram (`services/telegram_upgrades.py`, `TG_UPGRADES_ENABLED`) — владелец известен.
- **Блокчейн (скан и поток TonAPI):** листинги и апгрейды из него выключены (`ONCHAIN_LISTINGS_ENABLED=false`, `ONCHAIN_UPGRADES_ENABLED=false`): у них нет контакта владельца, они дублируют маркеты и шумят. Скан продолжает считать флоры, количество и атрибуты коллекций. **Продажи («GIFT SOLD!») пока приходят только из блокчейна** (`ONCHAIN_SALES_ENABLED=true`): у MRKT/Portals нет проверенного источника продаж; отключайте, только если алерты продаж не нужны.
- Листинги MRKT/Portals идут без контакта продавца и доходят только до фильтров с выключенной галочкой «Листинги: только если можно написать владельцу».

## Админка, мониторинг, данные и приватность

**Команды администратора** (только ID из `ADMIN_TG_IDS`): `/grant`, `/revoke`, `/users`, `/add_collection`, а также
`/ban <id>` и `/unban <id>` (забаненным алерты не отправляются), `/stats` (пользователи, подписки, фильтры, события и алерты
за сегодня и вчера, очередь ошибок), `/dlq [N]` и `/dlq_clear` (очередь `nft_dlq`), `/broadcast <текст>` + `/broadcast_confirm` (рассылка с подтверждением).

**Алерты администратору** (`services/health_monitor.py`, настройки `HEALTH_*`): сообщение в Telegram, когда диспетчер отстаёт
(`HEALTH_MAX_LAG`), растёт `nft_dlq` (`HEALTH_MAX_DLQ`), воркер владельцев/Telethon не отвечает, или в потоках нет новых событий
`HEALTH_STALL_MINUTES` минут. Пишет при появлении сбоя и при восстановлении, повторы — не чаще `HEALTH_REPEAT` секунд.

**Бэкапы и очистка:** Redis с AOF (`--appendonly yes`), `bash scripts/backup.sh` — дамп PostgreSQL (хранит 14 последних) и очистка
снимков флоров старше 90 и продаж старше 180 дней; добавьте в cron: `17 4 * * * cd ~/gifts/GiftTrackApp && bash scripts/backup.sh >> backups/backup.log 2>&1`.
Потоки событий ограничены `MAXLEN`.

**Приватность:** `/privacy` (что хранится), `/delete_me` — удаляет пользователя, фильтры, избранное и подписку.

**Сервер:** наружу должны быть открыты только 80/443 (HTTPS на nginx/через прокси) и SSH; порты Postgres и Redis наружу не публикуются (`ufw allow 22,80,443/tcp; ufw enable`).
Тестовый бот: отдельный `BOT_TOKEN` в `.env`.

### Статус, пауза, тихие часы, напоминание

`/status` — подписка, число фильтров, пауза и тихие часы; `/pause` и `/resume`; `/tz <часы от UTC>` и `/quiet <с> <до>` / `/quiet off` (тихие часы по вашему часовому поясу, по умолчанию UTC+3).
Диспетчер не шлёт алерты забаненным, поставившим паузу и в тихие часы. За 3 дня до конца подписки бот один раз напоминает о продлении
(`services/subscription_reminder.py`); после продления срок новый — напомнит снова. Админские команды работают только у админов, остальным `/stats` показывает их собственную статистику.

### Лента сигналов в мини-приложении

Вкладка «Лента» (`frontend/src/Feed.jsx`): последние алерты пользователя — «Апгрейды», «Листинги», «Продажи» — карточками
(название, модель · фон · символ, цена, метки типа/маркета/возраста, кнопки «Написать владельцу» и «Подарок»). Карточка пишется в Redis
(`feed:{uid}`, 200 последних, 7 дней) при успешной отправке алерта; API: `GET /api/feed?kind=upgrade|listing|sale`. Обновляется опросом раз в 8 с
(SSE — позже). Что осталось по разделу 19 ТЗ: токены и светлая тема, анимации, скелетоны, диалог редактора фильтра.

**Качество:** CI запускает `compileall`, `mypy` (старые модули исключены в `pyproject.toml`) и `pytest`. Состояние Track и допущения — в `docs/TRACK_REPORT.md`.
